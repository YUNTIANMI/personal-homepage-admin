## 1. 项目背景与目标

### 1.1 背景

博主罗辑，软件工程专业背景，需要一处能够长期沉淀并展示「技术文章 + 个人项目 + 个人名片」的独立站点。相比在 GitHub / 掘金 / CSDN 等平台发表内容，独立主页意味着：

- 内容与数据完全自持，不被平台规则与排版绑架；
- 统一、精致的个人品牌表达；
- 一个可当作"数字名片"对外分发的入口。

### 1.2 目标

1. 提供基于 **Markdown** 的博客内容发布与渲染能力，文章以本地 `.md` 文件形式管理；
2. 展示作者的**软件工程项目**，每个项目卡片可一键跳转 GitHub 仓库、在线 Demo 等外部链接；
3. 整体视觉 **简洁、高级、有程序员的酷炫感但不廉价**；
4. 站点为纯前端静态方案，可低成本构建并部署到任意静态托管（GitHub Pages / CloudBase / Vercel 等）。

### 1.3 非目标（本期不做）

- 不做用户系统、评论需登录、后台管理（评论可先接第三方如 Giscus，见 §7.7）；
- 不做富文本在线编辑器，内容一律以 Markdown 文件管理；
- 不做多作者 / 多人协作；
- 不依赖数据库与后端服务（部署期可按需引入 CDN / 云托管）。

## 3. 内容与信息架构

### 3.1 站点地图

```
罗辑个人主页
├── 首页 Home            —— 一句话自我介绍 + 亮点数据 + 精选文章 + 精选项目
├── 博客 Blog            —— 文章列表（支持标签 / 分类 / 归档）
│   └── 文章详情 Post     —— Markdown 渲染正文 + TOC + 元信息 + 上一篇/下一篇
├── 项目 Projects        —— 项目卡片网格，外链 GitHub / Demo / 文档
├── 关于 About           —— 软件工程专业履历、技能栈、时间线（可选）
└── 全局 Footer          —— 社交外链：GitHub / 掘金 / 邮箱 / RSS
```

### 3.2 导航

- 顶栏固定（桌面）：
  `logo` · 首页 · 博客 · 项目 · 关于 · [主题切换] · [GitHub 图标外链]
- 移动端：汉堡菜单折叠；文章页自动生成右侧 / 顶部 TOC（窄屏收起）。

## 4. 功能需求

### 4.1 博客与 Markdown 渲染（P0）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-01 | 文章以 Markdown 源文件管理，构建时加载 | 新增 `xxx.md` 即自动进入列表，无需改代码 |
| FR-02 | 支持 GFM（表格、删除线、任务列表、脚注、自动链接） | GFM 语法逐项实测通过 |
| FR-03 | 代码块**语法高亮**，行号可选，支持标题语言 | 语言标签渲染正确；明/暗主题下对比度达标 |
| FR-04 | 正文标题生成**目录 TOC**，可点击锚点跳转 | 长文滚动时高亮当前章节 |
| FR-05 | 文章元信息展示 | 标题 / 日期 / 标签 / 阅读时长 / 分类 |
| FR-06 | 安全渲染 | 默认转义 HTML、过滤危险标签与协议，防 XSS |
| FR-07 | 阅读体验 | 正文最大宽度约 70–75ch；行高、字距符合阅读规范 |

> 备选能力（排期后置）：文章内数学公式 KaTeX、自定义目录封面、图片懒加载 / 缩放预览。

### 4.2 项目展示与外部跳转（P0）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-08 | 项目以卡片形式展示 | 卡片含：封面(可选)、名称、简介、技术标签、Star(可选) |
| FR-09 | 卡片可配置外部链接并支持跳转 | `GitHub / Demo / Docs` 等链接，`target="_blank"` 且带 `rel="noopener"` |
| FR-10 | 空链接按钮置灰并禁止点击 | 无死链入口 |

### 4.3 个人名片信息（P0）

- 首页 Hero 展示：姓名「罗辑」、一句话定位（软件工程方向）、CTA（查看项目 / 联系我）。
- About 页补充：教育背景、技能栈（按熟练度分档）、职业时间线。

### 4.4 全局能力（P1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-11 | 明 / 暗主题切换 | 默认跟随系统，可手动覆盖并记忆（localStorage）；两套主题都必须通过对比度检查 |
| FR-12 | 全站响应式 | 375 / 768 / 1024 / 1440 四档无错乱，无横向滚动 |
| FR-13 | 文章检索 | 标题 + 标签 + 正文的即时搜索（纯前端，支持中文分词兜底为子串匹配） |
| FR-14 | 标签 / 分类聚合 | 点击标签可筛选同标签文章 |
| FR-15 | 阅读进度条 | 文章详情页顶部细进度条 |
| FR-16 | 页面切换 | 客户端路由切换 + 顶部滚动复位；骨架屏或过渡动画 |
| FR-17 | 404 页 | 定制 404（一句"Page not found"加回首页按钮） |

### 4.5 动效与质感（P1）

- 克制使用入场动画，统一 150–300ms 缓动，遵循 `prefers-reduced-motion`；
- Hero 区可加入轻量的"终端打字 / 光标闪烁"等程序员语义元素（可选、低俗感优先级最低）；
- 卡片 hover 反馈统一为：边框/阴影/图标位移，禁止布局抖动。

## 5. 视觉与体验设计规范（Design Direction）

### 5.1 关键词

`简洁 · 克制的暗色基调 · 等宽字体点缀 · 霓虹微量 · 界面克制 · 高级感`

- 参考气质：Linear / Vercel / GitHub 暗色、Svelte、Rust 官网、hack 风但收敛；
- 反面清单（明确不做）：五彩渐变堆砌、发光过强、廉价 3D、大面积 emoji、玻璃拟态滥用、闪烁跑马灯。

### 5.2 配色方向（候选，最终以高保真稿为准）

| 角色 | 深色（主推基调） | 浅色 |
| --- | --- | --- |
| 背景 | 深蓝黑 `#0B0F14` / `#0D1117` 级 | 近白冷灰 `#F7F8FA` |
| 表面 / 卡片 | 略亮一档 + 细边框（`rgba(255,255,255,0.08)`） | 白底 + `border-gray-200` |
| 正文 | 高对比冷白 `#E6EDF3` | `slate-900 #0F172A` |
| 次要文字 | `#8B949E` 级 | `#475569` 级（≥ 4.5:1） |
| 强调色 | 单主色系：荧光青 `#22D3EE` 或靛蓝 `#6366F1`（低饱和），仅用于链接 / 高亮 / CTA / 代码关键字 | 对应加深一档 |
| 语义色 | 代码与标签分层用（绿 / 紫 / 橙仅限语法高亮内部） | 同左 |

> 配色纪律：**主强调色 ≤ 2 个**，大面积只允许中性色；高亮不靠"亮"而靠"对比层次"。

### 5.3 字体

- 英文 / 数字 / 代码：`JetBrains Mono` 或 `Fira Code`（作为品牌点缀，Hero 标题、代码、编号可用）；
- 界面与正文（中文优先）：系统字体栈（`PingFang SC / Microsoft YaHei`）+ Latin 用 `Inter`；
- 标题可混排：中文大标题 + 英文等宽副标（如 `BLOG / PROJECTS` 角标），制造"工程感但不喧哗"。

### 5.4 界面语言与细节

- 按钮、图标统一用线性 SVG（lucide-react），**禁止 emoji 充当 UI 图标**；
- 细线、留白、数字编号（`01 / 02`）、键盘键帽样式、行内代码胶囊等"程序员彩蛋"点到为止；
- 圆角统一（卡片 12–16px，控件 8px），阴影柔和无扩散；
- 网格 / 噪点背景仅允许在 Hero 用极淡版本，正文区域保持纯净。

## 6. 技术选型建议

> 采用**纯前端静态站** + **内容即代码（Content-as-Code）** 的架构，与"Markdown 管理文章"的需求天然匹配。

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | React 18 + **Vite** + **TypeScript** | 开发体验好、构建快、生态成熟；也可整体升迁 Next.js 静态导出 |
| 样式 | Tailwind CSS + shadcn/ui 风格组件 | 原子化快速落地，风格统一，组件可访问性好 |
| 路由 | React Router（文件级布局） | 单页体验 + 可部署任意静态托管 |
| Markdown 管线 | `react-markdown` + `remark-gfm` + `remark-rehype` + `rehype-highlight`（或 shiki） | 渲染 GFM 与安全处理（默认转义 HTML） |
| 代码高亮 | shiki（质量优先）或 highlight.js | 与配色系统同源，避免刺眼默认主题 |
| 内容加载 | Vite `import.meta.glob` 批量导入 `content/**/*.md` | 新增 md 文件即自动注册，天然贴合 FR-01 |
| 日期 / 阅读时长 | `gray-matter` 解析 frontmatter + 字数估算 | 文章元信息零成本 |
| 图标 | lucide-react + Simple Icons（品牌 logo：GitHub 等） | 语义化、免字体依赖 |
| 评论（可选 P2） | Giscus（GitHub Discussions） | 无后端、与 GitHub 生态一致 |

### 6.1 目录结构（规划）

```
luoji-home/
├── content/
│   ├── posts/*.md          # 博文源文件（frontmatter: title/date/tags/desc/cover）
│   └── projects.json       # 项目数据（可后续迁移为 *.md + frontmatter）
├── src/
│   ├── components/         # 布局与通用组件（Navbar/PostCard/ProjectCard/Toc...）
│   ├── pages/              # 路由页面（Home/Blog/Post/Projects/About/404）
│   ├── lib/                # markdown.ts（解析管线）、utils.ts、内容加载器
│   ├── styles/             # 全局样式、主题 token、代码块主题
│   └── main.tsx
├── public/
└── docs/                   # 需求与设计文档
```

### 6.2 数据模型（草案）

文章 `frontmatter`：

```yaml
---
title: 深入理解 React 渲染调度
date: 2026-08-12
tags: [react, 前端]
category: 前端工程
description: 一句话摘要（列表与 SEO 用）
cover: /covers/xxx.png      # 可选
draft: false
---
```

项目数据字段：

```ts
interface Project {
  id: string;
  name: string;
  tagline: string;        // 一句话简介
  description?: string;   // 长描述（可选）
  tech: string[];         // 技术标签
  links: { label: string; href: string; }[];  // GitHub / Demo / Docs
  featured?: boolean;
}
```

## 7. 非功能需求

### 7.1 性能

- 首屏 LCP ≤ 2.5s（4G 模拟）；首屏优先关键 CSS，正文图片懒加载；
- 单页不引入重型依赖；代码高亮按需加载主题；
- Lighthouse（移动）Performance ≥ 90，Accessibility ≥ 95。

### 7.2 可访问性（a11y）

- 语义化标签 + 每个交互元素可聚焦、有焦点环；
- 颜色对比度正文 ≥ 4.5:1，图标辅助文字不依赖颜色单独传达状态；
- 图片 `alt`；键盘可完整浏览；支持 `prefers-reduced-motion`。

### 7.3 SEO

- 每页独立 `title` / `description` / `og:` 标签；文章页注入结构化数据；
- 站点地图与 RSS 生成（构建期）；合理的 URL 语义化（`/blog/:slug`）。

### 7.4 安全

- Markdown 默认转义 / 白名单协议；外链一律 `rel="noopener noreferrer"`。

### 7.5 兼容性

- 目标：最新两版 Chrome / Edge / Safari / Firefox；iOS ≥ 14、Android WebView 现代内核。

### 7.6 可维护性

- 内容与代码分离（改内容不碰代码、改代码不碰内容）；
- 组件风格统一、文案抽常量、主题 token 化管理。

### 7.7 隐私与第三方

- 评论（若接 Giscus）与站点统计需在隐私政策中说明；默认站点可无任何外呼请求，统计类脚本延后。

## 9. 验收标准（DoD 摘要）

1. 新增一篇 Markdown（含表格、代码、脚注、任务列表）即可自动出现在列表并可正常阅读；
2. 任意项目卡片均可跳转其配置的外部地址，且新窗口打开安全属性齐全；
3. 站点在明/暗两主题、四档屏幕宽度下均可正常阅读，无溢出与死链；
4. 代码高亮、TOC、标签筛选、文章搜索在样章数据上全部可用；
5. Lighthouse Accessibility ≥ 95、Performance ≥ 90（移动模拟）；
6. 全站无 emoji 冒充图标、无占位图片、无遗留 TODO 占位。

## 10. 关键假设与待确认问题

1. **博客与主页并重**：默认以"博客为主要内容 + 项目为重点卖点"设计首页信息权重，如倾向项目优先可在评审中调整；
2. 项目真实数据（仓库地址、简介、技术标签）需罗辑本人提供或后续填写；
3. 站点主基调默认深色，浅色作为完整适配而非附属；
4. 部署目标未定：默认产物可跑通"任意静态托管"，具体平台（GitHub Pages / CloudBase / 自有域名）待定；
5. 是否开放第三方评论（Giscus）本期默认不做，可在 M4 评审决定；
6. "罗辑"如需英文品牌标识 / 域名前缀（如 `luoji.dev`）请提供，用于字体与 SEO 设计。
