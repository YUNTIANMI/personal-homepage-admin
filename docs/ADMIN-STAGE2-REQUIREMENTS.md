## 3. 技术选型

> **总原则：不新增运行时依赖。** 全部能力用 Supabase 内置（Auth / DB / Storage）+ 现有库实现，保持产物体积与维护成本不变。

> 说明：下表保留 S2.1 / S2.5 相关选型备查；**经确认本期不实施**（草稿状态、置顶排序、文章直链、操作日志、软删除）。

### 3.1 关键决策

| # | 需求 | 选型 | 理由 | 替代方案（不采用的原因） |
| --- | --- | --- | --- | --- |
| 1 | 草稿 / 发布 | `posts.status text not null default 'published'` + `check (status in ('draft','published'))` | 加法迁移、现有行默认已发布、零风险 | 布尔 `published`（扩展性差）；独立草稿表（数据分裂） |
| 2 | 展示区只看已发布 | 展示端查询加 `.eq('status','published')` | 过滤下沉到数据层，展示组件无需感知 | 前端过滤（草稿会被拉到浏览器，不安全且浪费流量） |
| 3 | 置顶 / 排序 | `posts.pinned boolean default false` + `posts.sort int default 0` | 布尔直观可切换；`sort` 处理同组精细排序 | 只用 `sort`（置顶需魔法值）；改用 `position` 浮点（易冲突） |
| 4 | 图片存储 | **Supabase Storage**，`assets` bucket（public 读） | 与现有 Supabase 同源、免后端、CDN 直出 | 第三方图床（不可控）；Base64 内嵌（体积爆炸）；自建服务（违背无后端约束） |
| 5 | 上传权限 | Bucket `file_size_limit ≈ 5MB` + `allowed_mime_types: image/*`；Storage 策略：anon `select`、authenticated `insert/delete` 且调用 `is_admin_session_valid()` | 与阶段一会话有效期策略保持一致，访客无法上传 | 仅 `authenticated`（无法约束旧会话）；公开写（危险） |
| 6 | 对象命名 | `assets/YYYY/MM/<uuid>.<ext>` | 避免同名覆盖、便于按时间归档 | 原名上传（重名覆盖）；单一目录（文件多后难管理） |
| 7 | 编辑器插图 | 原生 `DataTransfer`（拖拽）+ `paste` 事件，无第三方编辑器 | 复用现有 Textarea + 预览，不引入重型编辑器 | 引入 ProseMirror/CodeMirror（体积与改造成本高，且偏离 Markdown 约束） |
| 8 | 站点配置 | 单行表 `site_profile`（`id text primary key default 'default' check (id='default')`） | 单管理员单份配置，读写简单、并发无冲突 | key-value 配置表（过度设计）；继续硬编码（无法后台编辑） |
| 9 | 配置兜底 | 展示区读取失败/未配置时回退 `src/lib/site.ts` 默认值 | 保证线上永不自爆空白页 | 直接删除 `site.ts`（故障时页面空白） |
| 10 | 配置下发 | 新增 `SiteProvider`（Context）+ 并入现有 store 拉取 | 与 posts/projects 同一次请求、无额外往返 | 每个组件各自请求（重复请求、状态不同步） |
| 11 | 导入导出 | 纯前端：`JSON.stringify` + `Blob` 下载；导入用 `FileReader` + 手写校验 | 零依赖、数据不出浏览器；批量 `upsert` 一次请求 | 引入 ajv 做 schema 校验（为一个功能加依赖）；后端导入接口（无后端） |
| 12 | 导入写入 | PostgREST 数组批量 `upsert`，按 100 条分批 | 单请求完成、可控错误粒度 | 逐条写入（请求过多）；直接覆盖全表（危险） |
| 13 | 修改密码 | `supabase.auth.updateUser({ password })`，改前先 `signInWithPassword` 验证旧密码 | 使用官方 API；验证旧密码可防「离开未锁屏被人改密」 | 依赖邮件重置（单管理员场景体验差） |
| 14 | 文章直链（P2） | 展示区改用 `react-router` 独立路由 + 部署 rewrite | 可分享 / 刷新不丢 / 利于收录 | 保留页内切换（现状，无法分享文章） |
| 15 | 软删除（P3） | `deleted_at timestamptz?` + 展示与后台统一过滤 | 改动小、可恢复 | 独立回收站表（关联复杂） |

## 5. 验收标准

1. 后台可上传图片并把链接插入正文，展示页图片正常显示、窄屏不溢出；
2. 访客无法上传（Storage 策略拒绝），且旧会话（超 7 天）同样被拒；
3. 站点配置在后台修改后，展示站点首页 / 关于 / 页脚刷新即生效；云端异常或表缺失时回退默认值不白屏；
4. 导出文件可再次导入并被正确识别；非法文件被拦截；
5. 导入「只新增 / 覆盖同 id，不删除」现有内容；
6. 修改密码后旧会话失效，需重新登录；
7. `typecheck` / `build` 通过；展示站点仍**零管理入口、零写逻辑**。

## 6. 风险与注意

| # | 风险 | 应对 |
| --- | --- | --- |
| 1 | 展示端漏加 `status` 过滤 → 草稿泄露 | 过滤下沉到数据层；验收时专门造一篇草稿验证 |
| 2 | Storage 策略只判角色、不判会话 | 策略内调用 `is_admin_session_valid()`，与阶段一一致 |
| 3 | 大图拖垮展示页 | Bucket 限 5MB + `image/*`；展示页图片 `loading="lazy"` |
| 4 | 导入覆盖线上数据 | 导入前强制导出备份 + 差异预览 + 二次确认 |
| 5 | 配置云端化后页面白屏 | 保留 `site.ts` 默认值兜底 |
| 6 | 文章直链改造影响部署 | 作为可选批次，单独排期并同步提供 rewrite 配置 |

### 8.1 验收标准逐条核对（对应 §5）

1. 展示区为**页内切换**，刷新会回到首页；如需可分享的文章直链，属于 S2.5 `FR2-ROUTE-01`，本期不做；
