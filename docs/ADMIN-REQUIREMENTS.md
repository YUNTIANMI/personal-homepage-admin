## 1. 项目背景与目标

### 1.1 背景

站点最初为纯前端 SPA（源项目 `personal-homepage`），数据存于 Supabase，但**没有任何鉴权**：

- 数据库 RLS 为「anon 匿名全量读写」，任何拿到前端 key 的人都能改数据；
- 页面对所有访客开放「新增 / 编辑 / 删除」入口。

为此复制出本项目作为管理端，并已完成：Supabase Auth 接入、RLS 收紧为「anon 只读 + authenticated 可写」、后台内容管理能力。

**进一步的问题**：源项目已冻结、不再改动，其页面上的管理按钮在 RLS 收紧后必然写入失败。因此把「对外展示」也收敛到本项目，形成**一个应用、两个区域**：访客看展示，管理员登录后管理。

### 1.2 目标

1. **对外展示站点**：任何人无需登录即可浏览首页 / 博客 / 项目 / 关于，**只读**，无任何管理入口；
2. **后台管理**：管理员登录后发布、维护文章与项目；
3. **鉴权与权限**：仅登录用户可写，且写权限受**会话有效期**约束；
4. **数据一致**：展示与后台共用同一份云端数据，后台发布后展示页即可见；
5. **视觉统一**：两个区域共用同一套设计 Token 与组件语言。

### 1.3 非目标（本阶段不做）

- 不做多管理员 / 角色权限 / 多人协作（单管理员场景）；
- 不做自建后端（纯前端 + Supabase；不使用 `service_role` 特权）；
- **不修改源项目 `personal-homepage`**（冻结）；
- 不做富文本编辑器（正文一律 Markdown）；
- 阶段一不做：草稿 / 发布状态、图片上传、站点配置可视化、数据导入导出。

## 3. 目标用户与使用场景

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 访客 | 打开站点的人，无需登录 | 快速了解作者、阅读文章、查看项目并跳转外链 |
| 管理员（罗辑本人） | 唯一账号，经 Supabase Auth 登录 | 发布 / 修订文章与项目，改完前台立即可见 |

主要场景：

1. **访客浏览**：打开 `/` → 首页 → 点「博客」读文章 → 点「项目」跳转 GitHub；
2. **发布文章**：`/login` 登录 → `/admin/posts` 新增 → 编写 Markdown → 预览 → 保存 → 展示页可见；
3. **批量清理**：多选 → 批量删除（二次确认）；
4. **维护项目**：新增 / 编辑项目，维护技术标签与外链；
5. **状态巡检**：仪表盘查看内容总量、云端连接与同步状态。

## 4. 信息架构与路由

```
luoji-admin（单应用）
├── /                      对外展示站点（只读，无需登录）
│     ├── 首页 Home / 博客 Blog / 项目 Projects / 关于 About
│     ├── 文章阅读（由博客列表进入）
│     └── 页内切换：点导航不改地址栏，刷新回到首页
├── /login                 登录页（展示站点不暴露该入口）
└── /admin                 后台管理（需登录）
      ├── /admin           仪表盘
      ├── /admin/posts     文章管理（列表 / 新增 / 编辑）
      └── /admin/projects  项目管理（列表 / 新增 / 编辑）
```

路由规则：

- 未登录访问 `/admin/*` → 重定向 `/login`，登录后跳回原页面；
- 已登录访问 `/login` → 直接进入 `/admin`；
- **其余任意路径**都会落到展示站点，对外不出现 404；
- 展示区采用**页内切换**（保留源项目的交互方式）：如需可分享的文章直链，后续可改为独立路由（需托管平台配置 rewrite 规则）。

## 6. 数据模型与字段规范

### 6.1 现有模型（阶段一，未做语义变更）

- `Post`：`id` / `title` / `date(yyyy-mm-dd)` / `category` / `tags[]` / `description` / `content` / `isSample?`
- `Project`：`id` / `name` / `tagline` / `tech[]` / `links[]` / `isSample?`
- `ProjectLink`：`id` / `label` / `href(http(s) 绝对地址)`
- 阶段一新增可选字段：`created_at?` / `updated_at?`（云端由触发器维护，本地写入时补盖）

### 6.2 表单校验规则

**文章**：标题非空（`maxLength=80`）；日期非空且可解析；分类可选（`maxLength=20`）；标签可选；摘要可选（`maxLength=140`）；正文 `trim().length >= 6`。

**项目**：名称非空（`maxLength=60`）；简介非空（`maxLength=120`）；技术标签可选；外链每行 label + href 齐备、`href` 需 `http(s)://`、**至少 1 条有效行**。

保存时统一 `trim()`；新增用 `uid()` 生成 id 并置顶；编辑保留原 id。

### 6.3 阶段二待新增字段（含兼容性约束）

| 表 | 字段 | 用途 | 风险 |
| --- | --- | --- | --- |
| `posts` | `status` | 草稿 / 发布 | 展示站点需同步过滤 `published`，须一起改 |
| `posts` | `pinned` / `sort` | 置顶、排序权重 | 展示站点需配合排序 |
| — | `site_profile` 单行表 | 站点资料云端化 | 展示区需改为读云端 |

> **兼容性原则**：只做加法（新增列）；**语义变更**必须展示与后台一起改，禁止单方面引入。

## 7. 云端与权限设计

### 7.1 数据库表与迁移脚本

表：`posts`、`projects`。迁移脚本（Supabase → SQL Editor 执行，均幂等）：

| 脚本 | 作用 |
| --- | --- |
| `supabase/migrations/0001_stage1_admin_base.sql` | `created_at` / `updated_at`、索引、`updated_at` 触发器；RLS 收紧为「anon 只读 + authenticated 可写」 |
| `supabase/migrations/0002_stage1_session_validity.sql` | `is_admin_session_valid()` 函数；写策略要求「会话未超过 7 天」 |

### 7.2 权限与会话有效期

| 角色 | 权限 |
| --- | --- |
| anon（访客） | 只读 `posts` / `projects`（展示站点 + 保活工作流依赖） |
| authenticated（管理员） | 可读写，且**会话须在有效期内** |

**双层校验**：

- **服务端（权威）**：`is_admin_session_valid()` 以 `auth.sessions.created_at` 为准，每次请求实时校验；过期会话的写入被 RLS 直接拒绝（`42501`），客户端无法绕过；
- **客户端（体验）**：`SESSION_MAX_AGE_MS`（默认 7 天）负责提醒与主动登出；服务端函数不可用时回退本地时间戳判断。

> 调整期限需**同时修改两处**：SQL 函数默认值 + `src/auth/AuthProvider.tsx` 的 `SESSION_MAX_AGE_MS`。

### 7.3 保活工作流

`.github/workflows/supabase-keep-alive.yml` 使用 anon key 查询 `posts`，**收紧 RLS 时必须保留 anon 的 `select`**，否则任务会 401 失败。

## 8. 交互与视觉规范

- **设计资产**：沿用 `styles.css` 的 CSS 变量 Token 与 `components/ui.tsx`（`Button` / `Input` / `Textarea` / `Field` / `Chip` / `EmptyState` / `PageHead` / `IconBtn` / `cn`）；
- **根字号阶梯**：< 1024px 100% → ≥1024px 106.25% → ≥1366px 118.75% → ≥1536px 131.25% → ≥1920px 150% → ≥2560px 175%；
- **单位**：字号 / 间距一律 rem，禁止固定 px；
- **排版**：`body` 全局 `font-weight: 500`，标题 700；
- **响应式**：页面级容器流体（`w-full` + 断点内距），内容级才限宽；表格 / 代码块局部横向滚动；视口严禁横向滚动；
- **不可破坏的机制**：`Dialog` 用 `createPortal` 挂 `body`；`.fade-up` 不写 `animation-fill-mode: both`；`.dialog-panel` 限高。

## 12. 关键假设与待确认问题

1. **单管理员模式**：仅一个管理员账号，后台不提供注册；
2. **展示区采用页内切换**：点导航不改地址栏、刷新回首页；如需文章直链（FR-SITE-11）需改为独立路由并在托管平台配置 rewrite；
3. **有效期 7 天**为当前取值，调整需同时改 SQL 与前端常量；
4. **阶段二字段**（`status` / `pinned` / `site_profile`）需要展示与后台一起改；
5. **源项目不再回归**：`personal-homepage` 冻结，任何前台变更都只在本项目进行。
